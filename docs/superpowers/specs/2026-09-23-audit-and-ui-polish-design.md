## 2. 深度审查设计（方案一：先审后修，一次成型）

四个审查代理并行，只读代码、不改代码：

| 审查线 | 范围 | 方法要点 |
|---|---|---|
| ① 服务端性能 | `server/` 全部路由与服务层 | N+1 查询、缺索引、全表扫、大文件/并发路径内存峰值、1C/1G 下线程与连接池、无谓全量读 |
| ② 技术债与正确性 | 全仓库 + roadmap 已列债务 | 逐条核实现状（孤儿 blob 竞态、Flyway 迁移、句柄关闭时机、MAX_FILE_SIZE 未强制等），另查新问题：吞异常、资源泄漏、边界条件 |
| ③ 安全面 | 认证/授权/分享/签名/上传下载 | 越权访问（改 id 读他人文件）、路径穿越、限流绕过、JWT/refresh 轮换缺陷、签名 URL 时效、分享撤销即时性、Web 端 token 存储 |
| ④ 客户端体验 | `app/shared` + Android 平台层 | 启动路径开销、列表分页与重排、缩略图缓存、滚动 recomposition 风险、上传下载错误反馈与重试、加载/空/错误三态完整性 |

## 3. UI 打磨视觉规范

### 禁止项

❌ 悬浮渐变 ❌ 发光描边 ❌ 花哨毛玻璃特效 ❌ 动画堆砌

### 基调（模仿 OneDrive / 百度网盘 / 夸克网盘，简洁大方）

1. **色彩**：背景纯色（浅色纯白 / 深色灰阶）；品牌色仅用于主按钮、选中态、进度条、分类图标；页面主体不出现第二种大面积颜色
2. **字体阶梯（4 级）**：页标题 20sp / 区块标题 16sp 中粗 / 正文 14sp / 辅助 12sp 灰；消灭字号跳变
3. **间距**：页边距 16dp、元素间距 8dp、列表行高 56-64dp；全局网格对齐，消灭 2dp 级错位
4. **卡片/行**：轻阴影（Elevation 1-2dp）与 1px 分割线**二选一全局统一**；圆角统一：卡片 12dp、按钮 8dp
5. **分类图标**：首页分类入口 = 扁平彩色圆角方块 + 白色线性图标（图片蓝 / 视频橙 / 文档紫…）
6. **交互逻辑**：长按多选 → 底部操作栏（下载/移动/删除/更多）；顶栏滚动后显底色；列表加载用骨架屏；空状态 = 图标 + 一句话 + 主按钮
7. **点击反馈**：所有可点元素有 ripple 或按下态，无一遗漏

幅度定位：**B（中等）**——允许个别明显不协调组件重做与小范围视觉层级调整，不动整体信息架构。

## 4. 已确认的缺陷（必须修复）

1. **壁纸未全覆盖**：壁纸只在部分容器生效，设置页、传输页没有。修法：壁纸挂到 App 最外层根容器，全页面透出；内容区按需加 **85% 纯色遮罩**（非毛玻璃）保证文字可读，深色模式下走两段式采样的对比度处理
2. **暗色模式文件夹文字黑字不可见**：疑似硬编码颜色未跟主题。归类「跨页面组件 → 深色模式」，定位代码修复

## 5. 打磨清单组织方式

按页面分组，每条三行式（现状 / 改法 / 归类）：

- 分组页面：登录 · 首页 · 文件 · 相册 · 预览 · 传输中心 · 设置 · 回收站 · 分享管理 · 对话框与吐司（跨页面组件单列）
- 清单与审查清单**一起**交用户勾选后再动手

## 6. 实施顺序与质量门

```
① 修 bug（壁纸、暗色字色、审查清单「严重」级）
   → 每批跑构建+测试，基线保持绿色
② UI 打磨：外壳（导航/顶栏/壁纸）→ 首页 → 文件 → 相册 → 其余页面
   → 外壳先行，因其为所有页面公共依赖
③ 审查清单勾选的次要/建议项
```

- 质量门：`./gradlew build` 全模块通过、服务端测试全绿
- 自查：每阶段走 requesting-code-review，重点查新引入的硬编码颜色/魔法数
